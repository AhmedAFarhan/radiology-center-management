# EGcare 1.0.0

First production release candidate of the Windows clinic application. Clinic PCs share the administrator PC's SQL Server and image archive over the local network.

- Patient registration, visits/calendar, examinations, reporting, payments, insurance, inventory and staff workflows in one desktop app.
- Arabic/English forms, Windows startup/tray behavior and saved sign-in under the existing session rules.
- Velopack updates from this repository, with an optional clinic share for offline PCs; explicit download and install/restart actions.
- Visible release version on login, setup, sidebar, profile and update screens.
- Development changes reach production through a version-checked development-to-main PR. Packaging/publication is manual only.

## Release readiness

Previous local verification passed 89 startup/component tests and a self-contained Windows publication. Real staging packages and a test-locator download were verified; these did not constitute a clean-machine installation or an installed upgrade/restart test. The release workflow runs the complete application CI again.

This release-preparation change passed a Windows Release build with zero warnings/errors, workflow linting, PowerShell syntax checks and the release-policy tests (version comparison, increasing builds, first-release bootstrap and rejection of mismatched manual inputs).

CI runs the protected-session/startup suite on Windows, where DPAPI is available. The Linux SQL container runs the business modules and direct database account workflows; startup/security tests are retained in the Windows job with their own uploaded results.

Complete installation/clinic acceptance on the intended machines before production publication. Use a new empty clinic database; keep development/demo records separate. Clinic configuration, database contents and any signing secrets are excluded from application packages.

Code signing is optional by the project owner's decision on 26 October 2026. No certificate or signing secret is needed for this release. Both GitHub publication and clinic-share updates support unsigned packages, while retaining SHA-256 verification, version checks and atomic feed publication. Optional signing can be configured later.

## First release inputs

After this PR is merged, run **Package and release EGcare** manually on **main** with `version=1.0.0`, `build_number=1` and `publish_release=false` for the review artifact. Use `publish_release=true` for the production release after acceptance. Do not run the old workflow on main before this PR is merged.
